# 일일 부동산·경매 투자 뉴스 하네스 (오케스트레이터)

대한민국 부동산·경매 투자 뉴스를 매일 수집·검증·통합하여 일일 브리핑으로 정리하고 다중 채널로 발송한다.

**실행 모드: 하이브리드 — 병렬 수집(서브 에이전트 3명, run_in_background) → 통합·검증(단일 서브 에이전트 1명)**
무인 정기 실행이라 팀 통신 오버헤드보다 독립 병렬 수집의 견고함이 우선이다. 수집가들은 서로 대화하지 않고 파일로만 산출한다.

**데이터 전달: 파일 기반** — 모든 중간 산출물은 `_workspace/{날짜}/`에, 최종 리포트는 `reports/`에 저장한다.

> 관련: `budongsan-news`(전역, 수동 단발 주간 리포트)는 별개다. 이 스킬은 매일·경매포함·자동발송 버전이다.

---

## Phase 0: 컨텍스트 확인 (실행 모드 판별)

먼저 `_workspace/`와 최신 리포트 존재 여부로 실행 모드를 정한다:

| 상황 | 모드 | 행동 |
|------|------|------|
| `_workspace/` 없음 또는 오늘 폴더 없음 | **초기/신규 실행** | 전체 Phase 1~5 수행 |
| 사용자가 "정책만/경매만 다시" 등 부분 수정 요청 | **부분 재실행** | 해당 수집가만 재호출 → 편집가 재실행 → 발송 |
| 사용자가 "어제 결과 기반/업데이트" 요청 | **갱신 실행** | 직전 리포트 경로를 에이전트에 전달해 변화 위주 갱신 |

날짜는 실행 시점 기준으로 계산한다(아래 Phase 1).

---

## Phase 1: 수집 기간 & 작업공간 설정

1. **수집 기간 결정**: 매일 실행이므로 기본은 **직전 영업일~당일**. 월요일이면 금~월(주말 포함). 사용자가 기간을 지정하면 그에 따른다.
2. 사용자에게 기준 기간을 한 줄로 명시(예: "2026-06-30 ~ 2026-07-01 기준").
3. 작업공간 생성: `_workspace/{YYYY-MM-DD}/` 폴더 준비.

---

## Phase 2: 병렬 뉴스 수집 (서브 에이전트 팬아웃)

3명의 수집가를 **동시에** 호출한다(`run_in_background: true`, `model: "opus"`). 각 에이전트 정의는 `.claude/agents/`에 있다. 프롬프트에 수집 기간·출력 경로·(후속 시)직전 산출물 경로를 전달한다.

| 에이전트 | 담당 카테고리 | 출력 파일 |
|----------|--------------|-----------|
| `policy-rate-collector` | 정책·규제 + 금리·거시경제 | `_workspace/{날짜}/01_policy-rate.md` |
| `market-region-collector` | 시장 동향 + 지역 + 분양·청약 | `_workspace/{날짜}/02_market-region.md` |
| `auction-collector` | 경매·NPL·급매·공매 | `_workspace/{날짜}/03_auction.md` |

세 에이전트 모두 완료될 때까지 대기 후 결과(건수·핵심)를 수집한다. 수집 방법론은 각 에이전트가 `references/categories-sources.md`를 읽어 따른다.

> 경매 정량 물건 데이터(courtauction.go.kr 스크래핑)는 기본 비활성. 사용자가 "물건도 긁어줘"라고 명시하면 auction-collector에 스크래핑 플래그를 켜서 전달한다.

---

## Phase 3~4: 통합 & 검증 (단일 서브 에이전트, 생성-검증 통합)

`news-editor`를 호출한다(`model: "opus"`). 프롬프트에 전달:
- 수집 기간, `_workspace/{날짜}/` 경로, 최종 저장 경로 `reports/{YYYY-MM-DD}-realestate-daily.md`
- (후속 시) 직전 리포트 경로

news-editor가 수행:
1. 3개 산출물 교차 검증(출처/날짜 누락, 수치 모순, 중복, 기간 일탈)
2. `references/report-template.md` 형식으로 최종 리포트 작성(경매 섹션 포함)
3. 발송용 200자 요약을 `_workspace/{날짜}/summary.txt`에 저장
4. 검증 이슈 목록 반환

---

## Phase 5: 다중 채널 발송

`scripts/deliver.py`로 발송한다:
```bash
python3 .claude/skills/realestate-news-daily/scripts/deliver.py \
  --report reports/{YYYY-MM-DD}-realestate-daily.md \
  --summary _workspace/{YYYY-MM-DD}/summary.txt
```
- 파일 저장은 이미 완료(경로 안내).
- macOS 알림은 기본 켜짐.
- 이메일/텔레그램은 `delivery-config.json` 설정 시 발송. 미설정이면 "disabled (skip)"으로 표시되며 실패가 아니다.

발송 결과(채널별 ✅/❌)를 사용자에게 보고하고, 리포트 경로와 핵심 요약을 함께 제시한다.

---

## 에러 핸들링

핵심 원칙: **1회 재시도 후 재실패 시 해당 결과 없이 진행하고 리포트에 누락을 명시**. 상충 데이터는 삭제하지 않고 출처 병기.

| 상황 | 대응 |
|------|------|
| 수집가 1명 실패 | 나머지로 리포트 작성, 해당 카테고리 "수집 실패 — 누락" 명시 |
| WebFetch 실패 | 에이전트가 WebSearch로 자동 전환(에이전트 정의에 명시) |
| 모든 수집가 실패 | "이번 회차 신규 뉴스 없음" 최소 리포트 + 사용자 알림 |
| 발송 채널 실패 | 다른 채널은 계속 발송, 실패 채널만 ❌로 보고 |
| 경매 스크래핑 차단 | 재시도 없이 뉴스 수집으로 대체, 리포트에 명시 |

---

## 정기 실행(스케줄링) 안내

매일 아침 자동 실행은 **crontab + `scripts/run-daily.sh`**로 등록되어 있다(평일 06:30). 래퍼는 headless `claude -p`로 이 스킬을 트리거하고 `logs/daily_YYYYMMDD.log`에 기록한다.

- 시각 변경: `crontab -e`에서 `30 6 * * 1-5` 수정.
- 일시 중지: 해당 cron 줄 앞에 `#` 추가.
- 로그 확인: `logs/daily_*.log`.
- 이메일/텔레그램 발송: `delivery-config.json` 설정 필요(`references/delivery-setup.md` 참조). 미설정 시 파일+데스크톱 알림만 발송된다.

## 테스트 시나리오

**정상 흐름**: "오늘 부동산 뉴스 모아줘" → Phase 0 초기 판별 → 기간 설정 → 수집가 3명 병렬 → 편집가 통합·검증 → deliver.py 발송 → 리포트 경로 + 요약 보고.

**에러 흐름**: auction-collector가 데이터 못 찾음 → 편집가가 경매 섹션 "이번 기간 신규 동향 없음, 직전 지표 유지"로 작성 → 나머지 정상 발송 → 보고에 경매 누락 명시.

**부분 재실행 흐름**: "정책 부분만 다시 해줘" → Phase 0 부분 재실행 판별 → policy-rate-collector만 재호출 → 편집가가 기존 리포트의 정책 섹션만 갱신 → 재발송.
