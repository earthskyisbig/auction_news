## 1. 요구사항 정의 (질문으로 범위 좁히기)

사용자: **"대한민국부동산 투자를 위한 뉴스를 정기적으로 모아주고자 해"**

에이전트가 먼저 현황을 감사(기존 `budongsan-news` 스킬 발견 = 수동 단발 주간 리포트)한 뒤,
설계를 가르는 3가지를 질문으로 확정:

| 질문 | 사용자 선택 |
|------|-----------|
| 수집 주기 | **평일 아침 6:30** |
| 관심 범위 | **경매 투자 + 일반 부동산 둘 다** |
| 전달 방식 | **파일 + 데스크톱 알림 + 이메일 + 텔레그램** |

> 💡 교훈: 애매한 요청은 바로 구현하지 말고, **결과물을 가르는 결정만** 골라 질문한다.

## 2. 하네스 아키텍처 설계

**실행 모드: 하이브리드** — 무인 정기 실행이라 팀 통신 오버헤드보다 독립 병렬 수집의 견고함을 우선.

```
[오케스트레이터 스킬: realestate-news-daily]
   │
   ├─ 병렬 수집 (서브 에이전트 3명, run_in_background)
   │   ├─ policy-rate-collector   (정책·규제 + 금리·거시경제)
   │   ├─ market-region-collector (시장·지역·청약)
   │   └─ auction-collector       (법원경매·NPL·급매)
   │        └→ 각자 _workspace/{날짜}/*.md 로 산출
   │
   ├─ 통합·검증 (단일 서브 에이전트)
   │   └─ news-editor  (교차검증 → 리포트 + 요약)
   │
   └─ 발송 (deliver.py: 파일/알림/이메일/텔레그램)
```

**핵심 설계 원칙:**
- 에이전트(누가) ↔ 스킬(어떻게) 분리
- 모든 에이전트 정의는 `.claude/agents/*.md` 파일로 (다음 세션 재사용 + 협업 프로토콜 명시)
- 파일 기반 데이터 전달(`_workspace/`), 최종 산출물만 `reports/`

## 4. 첫 실제 실행 (end-to-end 검증)

- 수집가 3명 병렬 가동 → 정책 7건 / 시장 11개 단지+지표 / 경매 8건+지표9
- 편집·검증가가 **카테고리 간 정합성 + 시점 불일치**까지 점검
  (예: 경매 낙찰가율은 5월 확정치라 수집기간 밖 → 기준일 병기 + 교차검증 권고)
- 리포트 생성: `reports/2026-07-01-realestate-daily.md` (오늘의 픽 + 30초 요약 + 6개 카테고리)

> 💡 교훈: 검증 에이전트는 "존재 확인"이 아니라 **경계면 교차 비교**(모집단 다른 수치 직접비교 금지 등)를 한다.

## 6. 확장 ①: 텔레그램 양방향

사용자: **"텔레그램에서 뉴스를 보거나, 지시를 할 수 있게 해줘"**

- **출력**: 요약 메시지 + **리포트 전문(.md 문서)** 첨부 (폰에서 열람)
- **입력**: `telegram_bot.py` — getUpdates 롱폴링 → 메시지를 `claude -p`로 실행 → 결과 회신
- **보안**: 인증된 chat_id(`[REDACTED_CHAT_ID]`)만 응답
- **상주**: launchd `KeepAlive`로 크래시·재부팅 자동 재시작

chat_id는 봇 토큰으로 `getUpdates` 호출해 자동 추출 (사용자가 봇에게 메시지 1개 전송 필요).

> 💡 반응형(우리 봇) vs 주도형(hermes류) 에이전트 차이 논의:
> 반응형=시키면 답함 / 주도형=스스로 감지해 먼저 알림 + 대화 기억 + 관심사 프로파일.

---

## 7. 확장 ②: 브라우저 스크래핑

사용자: **"아실, 호갱노노도 스크래핑으로 넣어줘. 국토부 뉴스·공지사항도."**

- 국토부·아실·호갱노노는 WebFetch/curl로는 막힘(리다이렉트·JS SPA)
- `render_page.py` — **Playwright headless로 렌더링된 본문 텍스트를 반환** → 수집가(LLM)가 파싱
- 사이트 셀렉터에 의존하지 않아 **구조 변경에 강함**, 실패 시 WebSearch 폴백
- headless로 작동 확인 → cron 무인 실행 OK (courtauction만 headful 필요)

> 💡 교훈: 사이트별 파서 대신 **"렌더 텍스트 통째로 → LLM이 추출"**이 훨씬 덜 깨진다.

## 8. 확장 ③: GitHub 커밋·푸시 + 리포트 자동 아카이빙

사용자: **"깃 커밋 푸시해줘"** → 이후 **"리포트도 매일 자동 아카이빙"**

### 🔒 이 세션 최고의 교훈 — 비밀값 유출을 두 번 막음

공개 저장소라 커밋 전 **비밀값 스캔을 습관화**:

1. **1차 적발**: `logs/telegram_bot.log`에 chat_id가 있어 커밋 중단 → `logs/`를 gitignore.
2. **2차 적발**: 내가 안전 가드에 **실제 봇 토큰을 하드코딩**하는 실수 → 스캔이 잡아냄
   → 토큰 리터럴 대신 **정규식 패턴**(`[0-9]{8,12}:AA[0-9A-Za-z_-]{30,}`)으로 교체.

```bash
# 커밋 전 항상 실행한 스캔
git grep -I -n -e "<token>" -e "<chat_id>" --cached
```

- `delivery-config.json`(토큰 보관)은 gitignore로 미추적
- `archive_report.sh`는 `reports/`만 add→commit→push하고, 매번 봇토큰 패턴 가드 후 푸시
- git 인증은 `gh auth setup-git`(자격증명 헬퍼)로 무인 푸시 지원

> 💡 교훈: **공개 저장소 push 전 비밀값 스캔은 필수.** 도구가 만든 파일에도 비밀값이 섞일 수 있다.

## 10. 강의 포인트 요약

1. **메타 스킬(`/harness`)로 에이전트 팀을 체계적으로 설계** — 즉흥 프롬프트가 아니라 재사용 가능한 파일로.
2. **요구사항은 질문으로 좁히고**, 결정이 끝나면 바로 실행.
3. **하이브리드 실행 모드** — 무인 자동화엔 견고함 > 협업 오버헤드.
4. **생성-검증 분리** — 편집·검증 에이전트가 경계면 교차 비교.
5. **깨지기 쉬운 스크래핑 대신 "렌더 텍스트 → LLM 추출"**.
6. **비밀값 위생** — gitignore + 커밋 전 스캔 + 패턴 가드, 공개 저장소는 특히.
7. **하네스는 진화한다** — 후속 요청마다 에이전트/스킬/스크립트를 점진 확장하고 변경 이력 기록.
